在本实验中，单行文本内单词若匹配成功，程序将立即记录并 统计本行词频 ，确报统计口径的严谨

KMP 分行实现：初始化init()

模式串预处理阶段

程序首先将所有待统计单词存储在固定大小的数组 word[M] 中，对每个单词构建对应的 KMP 前缀表 kmp[i]

核心逻辑

前缀表的计算遵循 KMP 原理：记录每个位置的 前后缀最长公共长度。在失配时快速回退，确保每个模式串在 O(len_word) 时间内完成扫描 

void init(){
    for(int i=0;i<num;i++){
        int idx_j=0;    //j: 已匹配长度
        kmp[i].resize(word[i].size());
        for(int k=1;k<(int)word[i].size();k++){
            while(idx_j&&word[i][idx_j]!=word[i][k])
                idx_j=kmp[i][idx_j-1];
            // 不匹配时尝试更短前缀，直至匹配或重置
            if(word[i][k]==word[i][idx_j]) idx_j++;
            kmp[i][k]=idx_j;
        }
    }
}

KMP 分行实现：匹配逻辑KMP_match()

在文本匹配阶段，程序逐行读取文本，并将整行转换为小写以实现大小写不敏感匹配

每行文本被视作一个整体字符串传入函数。对每个模式串，算法从行首开始逐字符比较

当字符不匹配时，利用前缀表快速回退模式串指针；匹配成功则将行号存入 pos[i] 并进行 词频统计，确保每词每行次数分别记录

//对于长度为len的单词，匹配复杂度为O(len*m)
void KMP_match(string &book, int line){
    for(int i=0;i<num;i++){
        int idx_j=0;
        for(int k=0;k<(int)book.size();k++){
            while(idx_j&&word[i][idx_j]!=book[k]) 
                idx_j=kmp[i][idx_j-1];
            //不匹配时则从匹配的长度为kmp[i][idx_j-1]的前缀找已匹配的最长前缀
            //本质即为尝试更短的前缀，直到找到一个匹配的前缀或者没有前缀了
            if(book[k]==word[i][idx_j]) idx_j++;
            if(idx_j==(int)word[i].size()){
                // 记录匹配位置，行号去重处理
                int siz=pos[i].size();
                if(!siz||pos[i][siz-1]!=line) 
                    pos[i].push_back({line,1}); 
                if(siz&&pos[i][siz-1]==line)
                    pos[i][siz-1].second++; 
                cnt[i]++;
            }
        }
    }
}

KMP 算法分析Complexity & Analysis

1. 复杂度分析

  • 时间复杂度：O(M + K × N)
    M 为所有词总长（预处理）；K 为词数，N 为文本长度（匹配时主串指针不回溯）
  • 空间复杂度：O(M + N)
    存储模式串、Next 数组及结果行号向量，内存占用极小

在本实验规模（K≤100）下效率极高，单次匹配复杂度仅为 O(当前行长)

2. 核心优缺点

  • 优势： 实现逻辑直观，内存占用极低，由于采用了 单行读取，符合“不跨行匹配”约束
  • 局限： 未进行单词分词处理，易发生子串误匹配（如查找 "he" 误匹配 "she"）
  • 瓶颈： 多模式串匹配时需重复扫描文本行，当 K 增大时性能会线性下降

如何解决？——— 分词处理 + 多模式串匹配

KMP 分词实现：数据结构与逻辑Word-level Analysis

分词核心思想：
程序利用 stringstream 将每行文本划分为独立词元(token)，确保匹配具有完整边界

坐标定位：
使用 pair<int,int> 记录匹配结果，能够精确追踪单词所在的行号及行内序号

相比分行实现，此方法有效解决了子串误匹配问题，定位更加精准

// 2.1 核心数据结构定义
const int N = 1e6+10;
const int M = 105;
string word[M], book;
int num = 0, line = 0, no = 0;
vector<pair<int,int>> pos[M]; // 存储：{行号, 单词序号}
vector<int> kmp[M];          // 每个模式串对应的Next表

// 文本处理阶段：引入分词逻辑
while(getline(fin, book)){
    no = 0; 
    if(book == "#") break;
    line++;
    stringstream ss(book); // 利用流进行单词切分
    string token;
    while(ss >> token){
        no++; // 行内单词计数器
        transform(token.begin(), token.end(), token.begin(), ::tolower);
        KMP_match(token, line, no); // 在分好的词元中精准匹配
    }
}

  • 适用场景： 中等规模文本处理，对单词边界匹配精度要求较高的任务

Trie 字典树：结构与插入Algorithm 3.2

Trie 字典树（前缀树）是实现多模式匹配的物理载体，通过共享公共前缀显著减少冗余比较

1. 映射逻辑：getnum 函数将 ASCII 为 33-126 的字符 统一映射至 0-100 范围内，实现空间的紧致分配

2. 动态构建：insert 函数在插入模式串时，若当前分支不存在则通过 idx++ 动态创建节点

3. 信息存储：在模式串结束的节点 p 处，用 out[p] 列表存储对应的模式串编号

const int N=1e5+10;        // N为总节点数
const int M=105,CH=100;    // M为单词数,CH为连接分支可能
string word[M],s,book;
vector<pair<int,int>> pos[M];     // 出现的行号和单词序号
int line=0,no=0,num=0,cnt[M];
int trie[N][CH],idx=1;       // idx 当前分配到的节点编号总数
vector<int> out[N];     // out[u] 存储节点u包含的模式串编号
int getnum(char x){
    int res=x-'0';
    if(res>=33&&res<=126) return res-33;
    return -1;
}

void insert(string str,int id){     // id:模式串编号
    int p=0,len=str.length();
    for(int i=0;i<len;i++){
        int c=getnum(str[i]);
        // 若无该分支，就创建新节点
        if(!trie[p][c]) trie[p][c]=idx++; 
        p=trie[p][c];                // 移动至子节点
    }
    out[p].push_back(id);
    // 走到节点p时，记录该路径代表的模式串编号
}

Trie 字典树：匹配逻辑Algorithm 3.2

匹配结果通过
vector<pair<int,int>> pos[M]
记录，每个元素保存出现的行号和词频

在匹配过程中，系统会检查 pos[id] 的末尾记录：若当前行已存在，则累加行内频次；若为新行，则新增记录

算法从单词的每个起始位置开始尝试向下遍历，直到路径中断或字符不合法

这种机制确保了即使单词中包含多个目标模式串，也能通过 out 列表完整提取所有结果

void Trie_match(string &book,int line){
    int len=book.length();
    //从单词的每个位置开始匹配
    for(int st=0;st<len;st++){
        int p=0;
        for(int i=st;i<len;i++){
            int c=getnum(book[i]);
            if(c==-1) break; //如果字符不合法，直接跳出循环
            if(!trie[p][c]) break; //没有这个字符分支，则没有这个串
            p=trie[p][c];
            for(int j=0;j<(int)out[p].size();j++){
                int id=out[p][j]; // 模式串编号
                int siz=pos[id].size();
                // 记录匹配位置，行号和该行中匹配到的次数
                if(!siz||pos[id][siz-1].first!=line)
                    pos[id].push_back({line,1});
                else if(siz&&pos[id][siz-1].first==line)
                    pos[id][siz-1].second++;
                cnt[id]++;
            }
        }
    }
}

Trie 字典树算法分析Complexity & Analysis

1. 复杂度分析

  • 时间复杂度：O(M + N × L)
    M 为模式串总字符数（构建）；N 为文本总字符数，L 为模式串平均长度（匹配）
  • 空间复杂度：O(M + N)
    利用前缀共享特性节省存储；M 相关于字典树节点，N 相关于结果记录与分词缓存

得益于前缀共享，空间利用率极高，且多模式串匹配效率显著优于重复调用的 KMP 算法

2. 核心优缺点

  • 优势： 支持一次扫描完成多模式匹配；精确控制单词边界逻辑；前缀共享有效减少冗余存储
  • 局限： 缺乏失配指针。匹配失败时需回退至根节点重新开始，在极端长文本下效率受限
  • 适用： 追求实现简洁与效率平衡的中等规模文本处理场景

进阶方案：引入失配指针 ——> AC 自动机

AC 自动机：核心数据结构Multi-Pattern Structure

核心架构：
AC自动机在Trie字典树基础上扩展，通过 trie_AC[N].next[100] 实现多模式前缀共享

状态跳转：
利用 fail 指针处理失配情况，指向最长可匹配前缀，实现一次扫描同时匹配多个模式串

结果映射：
每个节点维护 out 向量记录匹配到的词号。空间复杂度与节点数呈线性关系，适合大规模任务

AC 自动机：字符预处理与插入

预处理阶段：
每个单词通过 insert 函数逐字符插入 Trie 树。
节点通过 trie_AC[u].next[c] 指向子节点，若不存在则新建，通过前缀共享减少存储开销

终止标记：
单词插入完成后，在终止节点的 out 向量中记录模式串编号，实现多模式串的统一管理并为后续匹配提供结构基础

const int N=1e5+10;
const int M=105;
struct trie{
    int fail;           //AC自动机失配指针
    vector<int> out;    //以该节点结尾的模式串编号
    int next[100];       //该节点第c个字符分支指向的子结点编号
}trie_AC[N];

int getnum(char x){
    int res=x-'0';
    if(res>=33&&res<=126) return res-33;
    return -1;
}

void insert(string &s,int id){
    int p=0;
    for(int i=0;i<(int)s.size();i++){
        int c=getnum(s[i]);
        if(c==-1) continue;
        if(!trie_AC[p].next[c]) trie_AC[p].next[c]=idx++;
        p=trie_AC[p].next[c];
    }
    trie_AC[p].out.push_back(id); //标记单词结尾
}

    AC 自动机：失配指针构建build_fail()

    在构建Trie的基础上，算法进一步通过 build_fail 函数建立每个节点的 fail 指针

    fail 指针指向当前节点匹配失败时最长可匹配前缀节点，实现失配快速跳转，避免重复回溯，提高匹配效率

    该过程采用 BFS 遍历 Trie节点，并根据父节点的 fail 指针确定子节点的 fail 指向，保证整个 AC 自动机正确连接

    void build_fail(){
    queue<int> q;
    for(int i=0;i<100;i++){
        if(trie_AC[0].next[i]){
            trie_AC[trie_AC[0].next[i]].fail=0;
            //根节点的失配指针指向自己
            q.push(trie_AC[0].next[i]);
        }
    }
    while(!q.empty()){  //BFS构建失配指针
        int u=q.front();
        q.pop();
        for(int i=0;i<100;i++){  //枚举所有字节点 
            if(!trie_AC[u].next[i]){
                trie_AC[u].next[i]=trie_AC[trie_AC[u].fail].next[i];
                //如果没有这个分支，就指向失配指针的对应分支
                continue;
            }
            trie_AC[trie_AC[u].next[i]].fail=trie_AC[trie_AC[u].fail].next[i]; 
            //有这个分支，就指向失配指针的对应分支
            //子节点的fail指针指向当前节点fail指针指向的节点的第i个分支
            q.push(trie_AC[u].next[i]);
        }
    }
}

    AC 自动机：匹配函数AC_match()

    在文本处理阶段，程序逐行读取文本并按空格分词，每行 文本串 作为独立单词进行匹配

    对于每个字符，算法通过 next[c] 沿 Trie 节点前进，若字符非法或分支不存在则回到根节点重新匹配

    若到达节点且 out 非空，则表示匹配成功；确保每行记录一次，共同统计词频，使用 siz 进行判断，同时沿 fail 链向上查找重叠或嵌套单词

    核心价值：通过前缀共享与失配跳转，实现一次扫描完成所有目标单词统计，极大提高大规模文本处理效率 

    void AC_match(string &s,int line){
    int p=0;
    for(int i=0;i<(int)s.size();i++){
        int c=getnum(s[i]);
        if(c==-1){
            p=0;    //非法字符重新匹配
            continue;
        }
        p=trie_AC[p].next[c];
        int temp=p;
        while(temp){  //沿着失配指针向上找，看看有没有单词结尾
            for(int j=0;j<(int)trie_AC[temp].out.size();j++){
                int id=trie_AC[temp].out[j];
                int siz=pos[id].size();
                if(!siz||pos[id][siz-1].first!=line)
                    pos[id].push_back({line,1}); //记录匹配位置，行号和单词在行中的位置
                else if(siz&&pos[id][siz-1].first==line)
                    pos[id][siz-1].second++;
                cnt[id]++;
            }
            temp=trie_AC[temp].fail; //继续沿着失配指针向上找，看看还有没有其他单词结尾
        }
    }
}

    AC 自动机算法分析Complexity & Analysis

    1. 复杂度分析

    • 时间复杂度：O(M + N + S)
      M 为模式串总长；N 为文本总长；S 为总匹配次数；每个字符仅需一次扫描，接近线性最优
    • 空间复杂度：O(M + S)
      Trie 节点数组与 Fail 指针存储空间与 M 线性相关；匹配结果 pos[M] 随总匹配次数 S 动态增长

    相比 KMP 和 Trie 字典树，AC 自动机在大规模文本和多模式串（≥50个）匹配场景下优势巨大

    2. 核心优缺点

    • 优势： 多模式匹配最优算法，一次扫描完成全部统计；支持嵌套、重叠单词匹配；Fail 指针显著避免了重复扫描
    • 适用： 工业级文本处理、海量关键词过滤、以及对单次扫描效率有极致要求的文学研究场景

    进阶方向：结合 Aho-Corasick 自动机与分词策略，构建高速文学分析系统
